# report.md 골격

`pipeline.py render`가 `findings.json` + `analysis.json`에서 이 순서로 생성한다. 손으로 쓰지 않는다 — 손으로 쓰면 MD와 HTML의 숫자가 어긋난다.

결론을 맨 앞에 둔다. 독자(기획자)는 두 번째 화면까지 안 내려간다.

```
# {키워드} — 경쟁 상품 리서치 리포트
> 실행일 · 분석 대상 N곳 (본문 / 부록 / 제외) · 출처 확인 비율
> ⚠️ 경쟁사 자동 선정됨 — 검토 필요            ← 자동 선정일 때만
> ⚠️ 검증 에이전트를 거치지 않았다              ← verification.json 없을 때만
> 🚫 완료 판정 미통과 — 위험물                  ← check 실패일 때만
"확인된 경쟁사 N곳을 기준으로 작성했다."

## 결론                     ← analysis.conclusions, 각 항목에 근거 경쟁사
## 지표 요약                 ← 시간당 원가 중앙값 / 스프레드 / 출처 확인 비율 / TOPIK 보장 수
## 경쟁사 비교표             ← 상품 / 세그먼트 / 원가격 / 총 시수 / 시간당 / 신뢰도 / 출처
## 경쟁사 팩트시트           ← 본문 항목별 상세 표
## 시장 빈틈                 ← analysis.gaps (1-3개), 각 항목에 근거
## 우리 상품 제안 (1안)       ← analysis.proposal, 시간당 원가를 시장 중앙값과 나란히
## 미확인·추정 항목           ← 시수 추정, 계산 불가, 재계산, 검증 메모
## 완료 판정                 ← check 항목 체크박스
## 부록 A — 신뢰도 C          ← 본문 제외 항목과 사유
## 부록 B — 제외 항목         ← 출처 없음·스키마 위반
## 부록 C — 전체 출처         ← URL, 발행일, 확인일
```

## 문장 규칙 (Analyst용)

- 짧게, 판단은 분명하게. 각 결론은 판단 또는 숫자를 담는다.
- 확실하지 않은 것은 "추정"이라고 쓴다.
- 경쟁사별 개별 수치를 문장에 옮겨 적지 않는다. 수치는 표가 말한다 — 문장에서 다시 쓰면 반올림·오타로 표와 어긋난다. 구간 경계(예: "시간당 2만원 이하 구간")는 쓸 수 있다.
